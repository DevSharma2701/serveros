# Credentials and settings you need to provide

Everything ServeOS needs from outside, in the order you will need it. Each entry says what it
is, where to get it, and exactly where to put it.

**Two places hold settings:**

- **On this computer (development):** the file `D:\CLAUDE\ServerOS\.env`. Change a value, then
  restart the API (`pnpm dev:api`).
- **On the real server (production):** Render dashboard → your `serveos-api` service →
  **Environment**. Change a value and Render restarts the API. Front-end addresses are set in
  Cloudflare Pages → project → **Settings → Environment variables**, and need a new deploy.

**Rules:** never commit a secret, never paste one into chat or email, and never put one in a
variable starting with `VITE_` or `EXPO_PUBLIC_` (those are visible to anyone). The API checks
its settings when it starts and names anything that is wrong, without printing values. In the
app, **Setup → Go-live checklist** shows what is still on a placeholder.

## 1. GitHub repository
- **Get it:** github.com → New repository → **Private**.
- **Put it:** nowhere in `.env`. Tell me the repository address and I will connect and push.
- **Without it:** no automatic checks and nothing to deploy from.

## 2. Domain name
You will create three addresses on it (examples):

| Address | For |
|---|---|
| `app.yourdomain.com` | Web app and the guest QR page |
| `kitchen.yourdomain.com` | Kitchen display |
| `api.yourdomain.com` | API |

They must all be on the same domain, or sign-in will not stick.

## 3. Cloudflare
- **Get it:** cloudflare.com → add your domain (you change the nameservers at your registrar).
- **Put it:** two Pages projects, each with these variables:

| Variable | Web app project | Kitchen display project |
|---|---|---|
| `VITE_API_URL` | `https://api.yourdomain.com` | `https://api.yourdomain.com` |
| `VITE_KDS_URL` | `https://kitchen.yourdomain.com` | — |

These two are public addresses, not secrets.

## 4. Neon (database)
- **Get it:** neon.tech → new project → **Connection details**. Copy two strings: one with
  "Pooled connection" on, one with it off.
- **Put it (Render):**

| Variable | Value |
|---|---|
| `DATABASE_URL` | the **pooled** string |
| `DIRECT_URL` | the **direct** (not pooled) string |

- **Secret:** yes, both contain the database password.
- **Development placeholder:** your local database on port 5433 (already set).

## 5. Render (API hosting)
- **Get it:** render.com → New → Blueprint → choose the repository (uses `render.yaml`).
- **Put it (Render asks for these on first deploy):**

| Variable | Value |
|---|---|
| `WEB_URL` | `https://app.yourdomain.com` |
| `API_URL` | `https://api.yourdomain.com` |
| `CORS_ORIGINS` | `https://app.yourdomain.com,https://kitchen.yourdomain.com` |

Already set by the blueprint: `NODE_ENV=production`, `STORAGE_PROVIDER=database`.

## 6. JWT secrets
- `JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` protect sign-ins. Render generates both.
- To make them yourself: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` (run twice; the two must differ).
- Do **not** copy the development values from `.env` to production.
- Changing them later signs everyone out.

## 7. Resend (email)
- **Get it:** resend.com → **Domains** → add your domain and create the DNS records it shows
  (in Cloudflare) → wait for "Verified" → **API Keys** → create a key with "Sending access".
- **Put it:**

| Variable | Value |
|---|---|
| `EMAIL_PROVIDER` | `resend` |
| `EMAIL_API_KEY` | the key (starts with `re_`) |
| `EMAIL_FROM` | `Your Restaurant <no-reply@yourdomain.com>` — must be on the verified domain |

- **Placeholder until then:** `EMAIL_PROVIDER=dev`. Nothing is sent; on this computer the
  messages are readable at `http://localhost:4000/api/v1/dev/outbox`. In production that page
  does not exist, so without Resend nobody can be invited or reset a password (the
  `create-restaurant` command prints the owner's first link for exactly this reason).

## 8. Razorpay (online payment)
- **Get it:** razorpay.com → sign up. Test keys work at once; live keys need business KYC
  (start early).
  - **Account & Settings → API Keys → Generate Test Key**: gives a *Key Id* and a *Key Secret*
    (the secret is shown once).
  - **Account & Settings → Webhooks → Add New Webhook**:
    - URL: `https://api.yourdomain.com/api/v1/payments/webhooks/razorpay`
    - Secret: make up a long random string (16+ characters) and keep it
    - Events: **order.paid** and **payment.captured**
- **Put it:**

| Variable | Value |
|---|---|
| `PAYMENT_PROVIDER` | `razorpay` |
| `PAYMENT_API_KEY` | Key Id (`rzp_test_...`, later `rzp_live_...`) |
| `PAYMENT_API_SECRET` | Key Secret |
| `PAYMENT_WEBHOOK_SECRET` | the webhook secret you made up |

- **Placeholders until then:** on this computer `PAYMENT_PROVIDER=dev` (a simulator; refused in
  production). In production use `PAYMENT_PROVIDER=none`: guests can order from the QR code and
  pay staff at the counter; card/UPI are recorded by hand.
- **Going live:** generate live keys, create a second webhook in live mode, replace the three
  values. Test and live keys must not be mixed.
- **Testing on this computer:** Razorpay cannot reach `localhost`, so webhooks will not arrive
  here. Payments still complete, because the page's signed return and the once-a-minute check
  with Razorpay each confirm them.

## 9. Mobile app (later)
- Expo account (free), Apple Developer Program and Google Play Console (both paid, both yours).
- **Put it:** `apps/mobile/.env.local` → `EXPO_PUBLIC_API_URL=https://api.yourdomain.com` (public).

## Every setting, in one table

| Variable | Secret? | Development (`.env`) | Production |
|---|---|---|---|
| `NODE_ENV` | no | `development` | `production` |
| `PORT` | no | `4000` | set by Render |
| `DATABASE_URL` | **yes** | local database | Neon pooled string |
| `DIRECT_URL` | **yes** | local database | Neon direct string |
| `TEST_DATABASE_URL` | yes | local test database | not used |
| `JWT_ACCESS_SECRET` | **yes** | already generated | generated by Render |
| `JWT_REFRESH_SECRET` | **yes** | already generated | generated by Render |
| `WEB_URL` | no | `http://localhost:5173` | `https://app.yourdomain.com` |
| `API_URL` | no | `http://localhost:4000` | `https://api.yourdomain.com` |
| `CORS_ORIGINS` | no | localhost addresses | app and kitchen addresses |
| `PAYMENT_PROVIDER` | no | `dev` | `none`, then `razorpay` |
| `PAYMENT_API_KEY` | no (public id) | empty | Razorpay Key Id |
| `PAYMENT_API_SECRET` | **yes** | empty | Razorpay Key Secret |
| `PAYMENT_WEBHOOK_SECRET` | **yes** | already generated | your Razorpay webhook secret |
| `STORAGE_PROVIDER` | no | `local` | `database` |
| `EMAIL_PROVIDER` | no | `dev` | `resend` |
| `EMAIL_API_KEY` | **yes** | empty | Resend key |
| `EMAIL_FROM` | no | placeholder | address on your domain |
| `API_DOCS` | no | not set (docs on) | not set (docs off) |
| `SEED_DEMO_PASSWORD` | yes | already generated | **never set** |

## If a secret leaks
Replace it at its source and update the setting: Razorpay (regenerate key, change webhook
secret), Resend (delete the key, create another), Neon (reset the database password), JWT
secrets (new values; everyone signs in again). A table QR code that leaks is replaced in
**Setup → Table QR codes**.
